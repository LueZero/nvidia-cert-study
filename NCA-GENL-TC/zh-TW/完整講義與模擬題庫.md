## 📘 主題 1：機器學習與神經網路基礎

### 1.1 機器學習類型

| 類型 | 說明 | 範例 |
|------|------|------|
| **監督式學習** | 有標籤資料，學習輸入→輸出映射 | 分類、迴歸 |
| **非監督式學習** | 無標籤資料，發現資料結構 | 聚類、降維 |
| **半監督式學習** | 少量標籤 + 大量無標籤資料 | 文本分類 |
| **強化學習** | 透過獎勵/懲罰學習決策策略 | 遊戲 AI、RLHF |
| **自監督學習** | 從資料本身生成標籤 | GPT 預訓練（預測下一個 token） |

### 1.2 神經網路基礎

**基本元件：**
- **神經元（Neuron）**：接收輸入 → 加權求和 → 激活函數 → 輸出
- **權重（Weights）**：連接強度，訓練時更新
- **偏差（Bias）**：調整輸出的閾值
- **激活函數**：ReLU、Sigmoid、Tanh、Softmax

**常見架構：**
| 架構 | 特點 | 應用 |
|------|------|------|
| **FNN（前饋）** | 最基本架構 | 簡單分類 |
| **CNN** | 卷積層，擅長空間特徵 | 影像處理 |
| **RNN/LSTM** | 序列資料，有記憶能力 | 時序、早期 NLP |
| **Transformer** | 自注意力機制，平行處理 | LLM、NLP |

### 1.3 訓練流程

```
前向傳播 → 計算損失 → 反向傳播 → 更新權重
     ↑                                    |
     └────────── 重複多個 epoch ──────────┘
```

**核心概念：**
- **損失函數（Loss Function）**：衡量預測與實際的差距（交叉熵、MSE）
- **最佳化器（Optimizer）**：SGD、Adam、AdamW
- **學習率（Learning Rate）**：權重更新的步幅大小
- **Epoch**：完整遍歷一次訓練資料
- **Batch Size**：每次更新權重使用的樣本數
- **過擬合（Overfitting）**：模型在訓練資料上表現好，但泛化能力差
- **正則化（Regularization）**：L1/L2、Dropout 防止過擬合

## 📘 主題 2：Transformer 架構與 LLM

### 2.1 Transformer 架構

**核心創新：自注意力機制（Self-Attention）**
- 允許模型關注輸入序列中的所有位置
- 解決 RNN 的長距離依賴問題
- 支援平行運算（不像 RNN 需要順序處理）

**Transformer 組件：**
```
輸入 → Embedding → Positional Encoding
  → [Multi-Head Attention → Add & Norm → FFN → Add & Norm] × N 層
  → 輸出
```

| 組件 | 功能 |
|------|------|
| **Embedding** | 將 token 轉為固定維度的向量 |
| **Positional Encoding** | 加入位置資訊（Transformer 本身不知道順序） |
| **Multi-Head Attention** | 多個注意力頭平行計算，捕捉不同面向的關係 |
| **Feed-Forward Network** | 對每個位置獨立做非線性變換 |
| **Layer Normalization** | 穩定訓練過程 |

### 2.2 LLM（Large Language Models）

**關鍵概念：**
- **Token**：文本的最小處理單位（可能是字詞、子字詞或字元）
- **Tokenizer**：將文本拆分成 token（BPE、WordPiece、SentencePiece）
- **Context Window**：模型一次能處理的最大 token 數
- **Parameters**：模型的可學習權重數量（GPT-4 級別：數千億）

**LLM 類型：**
| 類型 | 架構 | 代表模型 |
|------|------|----------|
| **Decoder-only** | 只有 Decoder，自迴歸生成 | GPT 系列、LLaMA |
| **Encoder-only** | 只有 Encoder，理解語義 | BERT |
| **Encoder-Decoder** | 完整 Transformer | T5、BART |

### 2.3 預訓練與微調

**預訓練（Pre-training）：**
- 在海量無標籤文本上自監督學習
- 學習語言的通用知識和模式
- 需要大量運算資源

**微調（Fine-tuning）：**
| 方法 | 說明 | 資源需求 |
|------|------|----------|
| **Full Fine-tuning** | 更新所有參數 | 極高 |
| **LoRA** | 低秩適應，只更新少量參數 | 低 |
| **QLoRA** | 量化 + LoRA | 更低 |
| **Adapter** | 插入小型可訓練模組 | 低 |
| **Prefix Tuning** | 在輸入前加可學習前綴 | 低 |

## 📘 主題 3：Prompt Engineering

### 3.1 提示工程基礎

**Prompt 結構：**
1. **指令（Instruction）**：告訴模型要做什麼
2. **上下文（Context）**：提供背景資訊
3. **輸入（Input）**：要處理的具體資料
4. **輸出格式（Output Format）**：指定回應格式

### 3.2 提示技巧

| 技巧 | 說明 | 範例 |
|------|------|------|
| **Zero-shot** | 無範例，直接問 | "翻譯以下句子" |
| **Few-shot** | 提供幾個範例 | "範例1:... 範例2:... 現在處理:" |
| **Chain-of-Thought** | 要求逐步推理 | "請一步一步思考" |
| **Role Prompting** | 指定角色 | "你是一位資深 Python 工程師" |
| **Self-Consistency** | 多次生成取共識 | 多次推理取最常見答案 |

### 3.3 溫度與取樣參數

| 參數 | 功能 | 效果 |
|------|------|------|
| **Temperature** | 控制隨機性 | 低→確定性，高→創造性 |
| **Top-k** | 限制候選 token 數 | 只從前 k 個最可能的 token 中選 |
| **Top-p（Nucleus）** | 機率累積閾值 | 動態調整候選池大小 |
| **Max tokens** | 最大生成長度 | 控制輸出長度 |

## 📘 主題 4：對齊（Alignment）

### 4.1 RLHF（Reinforcement Learning from Human Feedback）

```
步驟 1：監督式微調（SFT）
  → 用人類示範的高品質回應微調預訓練模型

步驟 2：訓練獎勵模型（Reward Model）
  → 人類對多個回應進行排序
  → 訓練模型預測人類偏好

步驟 3：RL 最佳化（PPO）
  → 使用獎勵模型的回饋來最佳化策略
  → 平衡有用性和安全性
```

### 4.2 對齊目標

- **有幫助的（Helpful）**：回答有用、準確
- **無害的（Harmless）**：不產生有害內容
- **誠實的（Honest）**：承認不知道的事情，不編造

### 4.3 DPO（Direct Preference Optimization）

- RLHF 的簡化替代方案
- 不需要單獨的獎勵模型
- 直接從偏好資料最佳化策略

## 📘 主題 5：RAG 與 LLM 部署

### 5.1 RAG（Retrieval-Augmented Generation）

```
使用者問題 → 向量搜尋（檢索相關文件）→ 將文件作為上下文 → LLM 生成答案
```

**RAG 組件：**
1. **文件分塊（Chunking）**：將文件切分成適當大小的段落
2. **Embedding 模型**：將文本轉為向量表示
3. **向量資料庫**：儲存和搜尋向量（FAISS、Milvus、Pinecone）
4. **檢索器（Retriever）**：根據查詢找到最相關的文件
5. **LLM 生成器**：結合檢索結果生成最終答案

**RAG 的優勢：**
- 解決 LLM 知識過時問題
- 減少幻覺（Hallucination）
- 不需要重新訓練模型
- 可引用資料來源

### 5.2 LLM 部署與推論最佳化

| 技術 | 說明 |
|------|------|
| **量化（Quantization）** | FP32→FP16→INT8→INT4 減少模型大小 |
| **KV Cache** | 快取已計算的 Key-Value 對，加速自迴歸生成 |
| **Batching** | 批次處理多個請求，提高 GPU 利用率 |
| **Model Parallelism** | 將大模型分布到多個 GPU |
| **Speculative Decoding** | 用小模型初步生成，大模型驗證 |

### 5.3 NVIDIA 推論工具

- **TensorRT-LLM**：LLM 推論最佳化引擎（量化、層融合，降低延遲提升吞吐量）
- **NVIDIA NIM**：預優化的推論微服務（標準 API 快速整合）
- **Triton Inference Server**：多模型推論服務平台（支援 ONNX、PyTorch、TensorRT）

### 5.4 NVIDIA 基礎設施與工具定位

| 工具 | 定位 | 說明 |
|------|------|------|
| **NeMo Framework** | 訓練/微調 | 端到端 LLM 訓練，原生支援 LoRA |
| **NeMo Guardrails** | 安全護欄 | 規則限制模型回覆邊界，防止越獄 |
| **NeMo Retriever** | RAG 部署 | 企業級檢索系統，降低幻覺 |
| **RAPIDS (cuDF, cuML)** | 資料處理 | GPU 加速分析，相容 Pandas |
| **ONNX** | 模型互通 | 跨框架標準，搭配 ORT 部署至不同硬體 |
| **MIG (Multi-Instance GPU)** | 硬體分配 | 單張 GPU 切分為多個獨立實例 |
| **NGC Catalog** | 資源庫 | 官方容器、預訓練模型、開發套件 |
| **NVIDIA AI Enterprise** | 企業平台 | 雲原生 AI 軟體，長期維運支援 |
| **Base Command** | 叢集管理 | DGX 資料中心作業系統 |

> ⚡ Triton = 推論伺服器；TensorRT = 底層運算最佳化。量化是為了省記憶體與降延遲，不是提升準確度。

## 📘 主題 6：資料分析、實驗設計與軟體開發

### 6.1 資料前處理

- **文本清理**：去除 HTML、特殊字元、正規化
- **Tokenization**：BPE（Byte-Pair Encoding）最常用
- **詞形還原（Lemmatization）**：根據詞性規則還原原型（running→run），語意一致性比截字尾好
- **資料去重**：移除重複的訓練樣本
- **資料品質篩選**：過濾低品質、有害內容
- **EDA（探索性資料分析）**：微調前的健康檢查，分析分布、長度、標籤平衡等

### 6.2 評估指標

| 指標 | 用途 |
|------|------|
| **Perplexity** | 衡量語言模型的語言建模能力（越低越好） |
| **BLEU** | 機器翻譯品質（n-gram 精確度；⚠️ 分數高只代表接近參考文本，不代表字彙量增加） |
| **ROUGE** | 摘要品質（n-gram 召回率，重點在有沒有漏掉重要資訊） |
| **F1-Score** | 分類品質（精確率與召回率的調和平均，適合不平衡資料） |
| **Human Evaluation** | 人類評估（最可靠但最貴） |
| **MMLU** | 多領域知識基準測試 |

### 6.3 Python LLM 生態系

| 工具/框架 | 用途 |
|-----------|------|
| **Hugging Face Transformers** | 預訓練模型載入和使用 |
| **LangChain** | LLM 應用開發框架 |
| **LlamaIndex** | RAG 應用框架 |
| **vLLM** | 高效推論引擎 |
| **PEFT** | 參數高效微調 |
| **Weights & Biases** | 實驗追蹤和管理 |

### 6.4 模型訓練與部署實務

- **A/B 測試**：模型上線後 50/50 流量分配比較指標，再決定全面切換
- **災難性遺忘**：微調後原有能力退化，可用 LoRA、資料混合緩解
- **波束搜尋（Beam Search）**：保留多條候選路徑生成更穩定的輸出
- **All-Reduce**：多 GPU 分散式訓練的梯度同步機制
- **擴展定律（Scaling Laws）**：增加參數/資料/算力能持續提升能力

### 6.5 可信賴 AI（Trustworthy AI）

- **偏見（Bias）**：訓練資料偏見導致不公平結果
- **幻覺（Hallucination）**：模型生成看似合理但錯誤的內容
- **可解釋性（Explainability）**：理解模型為何做出某個決策
- **隱私（Privacy）**：保護訓練資料中的個人資訊
- **安全性（Safety）**：防止模型被用於有害目的
- **NeMo Guardrails**：NVIDIA 的 AI 安全防護框架
- **內容來源憑證（Content Credentials）**：透過 C2PA 標準追溯 AI 生成內容來源（CAI 聯盟推動）

### Q12
**為什麼 Transformer 架構需要位置編碼？**

A) 減少模型大小  
B) 因為自注意力機制本身沒有位置概念，需要提供序列順序資訊  
C) 加密輸入資料
