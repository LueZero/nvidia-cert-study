## 1.2 神經網路基礎

### 核心概念

```
輸入 → [加權求和 + 偏差] → 激活函數 → 輸出
```

- **權重（Weights）**：連接強度，訓練時不斷調整
- **偏差（Bias）**：微調輸出的基準值
- **激活函數**：讓網路能學「非直線」的關係

### 激活函數比較表

| 函數 | 公式 | 白話說明 | 用在哪 |
|------|------|---------|--------|
| **ReLU** | $f(x) = \max(0, x)$ | 正值照輸出、負值變 0 | CNN、通用深度學習預設 |
| **Sigmoid** | $\sigma(x) = \frac{1}{1+e^{-x}}$ | 壓縮到 0~1 之間 | 二元分類輸出層 |
| **Tanh** | $\tanh(x)$ | 壓縮到 -1~1 之間 | RNN/LSTM 隱藏層 |
| **GELU** | $f(x) = x \cdot \Phi(x)$ | 像 ReLU 但更平滑 | **Transformer（BERT、GPT）** |
| **Softmax** | $\frac{e^{z_i}}{\sum e^{z_j}}$ | 變成機率分佈（總和=1） | 多分類輸出層、Attention 權重 |

> ⚡ **考試重點**：  
> - 不加激活函數 → 多層網路 = 一層線性模型（白做工）  
> - Transformer 用 **GELU** 或 **Swish**  
> - 多分類 → **Softmax**；二元分類 → **Sigmoid**

### 損失函數

| 函數 | 公式 | 白話說明 | 用途 |
|------|------|---------|------|
| **MSE** | $\frac{1}{n}\sum(y-\hat{y})^2$ | 預測值和真實值差距的平方平均 | 迴歸（預測數字） |
| **MAE** | $\frac{1}{n}\sum\lvert y-\hat{y}\rvert$ | 預測值和真實值差距的絕對值平均 | 迴歸（對異常值穩健） |
| **Cross-Entropy** | $-\sum y\log\hat{y}$ | 衡量兩個機率分佈的差異 | 分類、LLM 訓練 |
| **KL Divergence** | $\sum P(x)\log\frac{P(x)}{Q(x)}$ | 一個分佈和另一個分佈有多不同 | 知識蒸餾 |

> ⚡ MSE 對大誤差懲罰很重（平方）；MAE 對異常值比較穩健。

### 優化器

| 優化器 | 白話說明 | 用在哪 |
|--------|---------|--------|
| **SGD** | 最基本：走一步看一步 | CNN 訓練 |
| **Adam** | 聰明版：自動調整每個方向的步幅 | 通用 |
| **AdamW** | Adam 的改良版：weight decay 正確解耦 | **Transformer/LLM 訓練標準** |

### 反向傳播

**白話**：從輸出往回算，告訴每個權重「你該往哪邊調、調多少」。數學上就是連鎖律（Chain Rule）一層一層算梯度。

### 訓練核心概念

| 概念 | 說明 |
|------|------|
| Epoch | 所有訓練資料看過一輪 |
| Batch Size | 一次看幾筆資料才更新一次權重 |
| Learning Rate | 每次調整權重的步幅大小 |
| Warmup | 開頭先小步走，再逐漸加速 |
| 過擬合 | 背答案但不會舉一反三 → 用 Dropout、正則化解決 |
| 欠擬合 | 連答案都背不起來 → 加大模型、延長訓練 |

### 正則化方法

| 方法 | 說明 |
|------|------|
| **Dropout** | 訓練時隨機關掉部分神經元，防止過度依賴 |
| **Weight Decay** | 限制權重不要太大 |
| **Layer Normalization** | 對每層做標準化 → **Transformer 使用此方法** |
| **Early Stopping** | 驗證集表現不進步就停止訓練 |

## 1.3 CNN、RNN、LSTM

| 架構 | 擅長什麼 | 白話說明 | 限制 |
|------|---------|---------|------|
| **CNN** | 影像 | 用小濾波器掃描圖片找特徵 | 不擅長序列 |
| **RNN** | 序列 | 有記憶力，一個字一個字看 | 長句子會忘記前面（梯度消失） |
| **LSTM** | 長序列 | RNN 升級版，加了「門」控制記什麼忘什麼 | 仍然無法平行處理 |
| **Transformer** | 通用 | 一次看全部，用注意力找關係 | 長序列計算量大（O(n²)） |

> ⚡ **考試重點**：CNN 的優勢是「參數共享」和「平移不變性」。LSTM 用「門控機制」解決梯度消失。

## 1.4 Transformer 架構（★★★ 超重點）

### 核心創新：Self-Attention

**白話**：讓每個字都能「看到」句子裡所有其他字，並計算出「誰跟我最相關」。

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

| 符號 | 意思 | 白話比喻 |
|------|------|---------|
| Q（Query） | 我在找什麼 | 你的問題 |
| K（Key） | 我能提供什麼 | 書本的標題 |
| V（Value） | 實際的內容 | 書本的內文 |
| √d_k | 縮放因子 | 防止數字太大導致 Softmax 飽和 |

**計算流程**：
```
Q×K^T → 除以 √d_k → Softmax（得到注意力權重）→ 乘以 V → 輸出
```

### Multi-Head Attention

把 Q/K/V 分成多組（多個 head），各自獨立算注意力，最後拼接。  
**好處**：不同 head 可以關注不同面向（有的看語法、有的看語義）。

### 位置編碼（Positional Encoding）

| 方法 | 用在哪 | 特點 |
|------|--------|------|
| Sinusoidal（sin/cos） | 原始 Transformer | 不需要訓練、可外推 |
| Learned Embedding | BERT | 可訓練的位置向量 |
| RoPE（旋轉位置） | LLaMA、Mistral | 支援更長序列 |
| ALiBi | 部分模型 | 在注意力分數加線性偏差 |

### Transformer 完整組件

```
輸入 → Token Embedding + Positional Encoding
  → [Multi-Head Attention → Add & Norm → FFN → Add & Norm] × N 層
  → 輸出
```

### 三種架構變體

| 架構 | 注意力方式 | 代表模型 | 用途 |
|------|-----------|---------|------|
| **Encoder-only** | 雙向（看前也看後） | BERT, RoBERTa | 理解任務（分類、命名實體） |
| **Decoder-only** | 單向（只看前面） | GPT, LLaMA | 生成任務（對話、寫作） |
| **Encoder-Decoder** | 雙向 + 單向 | T5, BART | 轉換任務（翻譯、摘要） |

> ⚡ **考試重點**：  
> - GPT = Decoder-only（自迴歸，逐字生成）  
> - BERT = Encoder-only（遮罩語言模型，雙向理解）  
> - 現代 LLM 多用 Decoder-only（因為生成能力強、架構簡單易擴展）

## 1.5 LLM 基礎知識

### 關鍵術語

| 術語 | 白話解釋 |
|------|---------|
| Token | 文本的最小處理單位（可以是字、子詞或字元） |
| Context Window | 模型一次能看的最大長度（GPT-4: 128K tokens） |
| Parameters | 模型的「腦容量」（GPT-3: 175B 參數） |
| Autoregressive | 逐字生成：根據前面已有的字預測下一個 |

### 預訓練目標

| 目標 | 模型 | 做法 |
|------|------|------|
| CLM（Causal LM） | GPT | 預測下一個 token |
| MLM（Masked LM） | BERT | 預測被遮住的 token（隨機 15%） |

### Tokenization（分詞）

| 方法 | 用在哪 | 合併策略 |
|------|--------|---------|
| **BPE** | GPT 系列 | 把最常出現的字元對合併成新符號 |
| **WordPiece** | BERT | 合併能讓整體機率最高的 |
| **SentencePiece** | LLaMA, T5 | 語言無關，直接處理原始文本 |

### 重要 LLM 模型

| 模型 | 架構 | 特點 |
|------|------|------|
| GPT-4 | Decoder-only (MoE) | 多模態、最強通用 |
| LLaMA 2/3 | Decoder-only | Meta 開源、RoPE、GQA |
| Mistral/Mixtral | Decoder-only (MoE) | Mixture of Experts |
| BERT | Encoder-only | 雙向理解 |
| T5 | Encoder-Decoder | 所有任務統一為 Text-to-Text |

### Scaling Laws & 湧現能力

- **Scaling Laws**：模型越大 + 資料越多 + 算力越強 = 性能持續進步
- **湧現能力**：小模型做不到、大模型突然能做的事（如多步推理、程式碼生成）
- **Chinchilla 法則**：模型大小和資料量要等比增加才最划算

## 1.6 Prompt Engineering

### 提示策略

| 策略 | 說明 | 範例 |
|------|------|------|
| **Zero-shot** | 只給指令 | "翻譯以下句子為法文：..." |
| **Few-shot** | 給 2-5 個範例 | "正面→Positive, 負面→Negative, 現在分類：..." |
| **Chain-of-Thought** | 要求逐步推理 | "Let's think step by step" |
| **ReAct** | 推理+行動交替 | 讓模型搜尋、計算、再回答 |
| **Self-Consistency** | 生成多次取多數 | 多次推理取最常見答案 |

### 生成參數

| 參數 | 白話說明 | 低值效果 | 高值效果 |
|------|---------|---------|---------|
| **Temperature** | 控制隨機性 | 穩定、確定性 | 有創意、多變化 |
| **Top-k** | 只從前 k 個最可能的選 | 更集中 | 更多元 |
| **Top-p** | 從累積機率達 p 的詞中選 | 更確定 | 更多樣 |
| **Max tokens** | 最多生成幾個字 | 短回答 | 長回答 |

> ⚡ **考試重點**：  
> - Temperature=0 → 完全確定性（每次輸出一樣）  
> - 事實問答用低 Temperature；創意寫作用高 Temperature  
> - Top-p 是「動態」決定候選數量（vs Top-k 是固定數量）

### Prompt 安全

- **Prompt Injection**：使用者在輸入中偷塞惡意指令
- **防禦方式**：輸入驗證、輸出過濾、指令與資料分離、NeMo Guardrails

## 1.7 Alignment（對齊）

### RLHF 三階段

```
Stage 1: SFT（監督式微調）
  用人類寫的高品質回答微調模型
      ↓
Stage 2: Reward Model（獎勵模型）
  人類對多個回答排序 → 訓練模型判斷好壞
      ↓
Stage 3: PPO（強化學習）
  用獎勵模型的分數指導模型持續改進
```

### DPO（Direct Preference Optimization）

- RLHF 的簡化版：不需要獎勵模型
- 直接從「好回答 vs 壞回答」的配對資料學習
- 更穩定、更容易實作

### RLHF vs DPO 比較

| 面向 | RLHF | DPO |
|------|------|-----|
| 獎勵模型 | 需要（額外訓練） | 不需要 |
| 計算成本 | 高（多個模型） | 低（單模型） |
| 穩定性 | 較低（PPO 難調） | 較高 |
| 實現複雜度 | 高 | 低 |

### Constitutional AI

Anthropic 提出：讓 AI 根據一套「憲法」（原則清單）自我批評、自我改進。

## 2.2 RAG 架構（Retrieval-Augmented Generation）

### RAG 流程（★★★ 必懂）

```
1. 文件載入 → 2. 切塊(Chunking) → 3. Embedding 向量化 → 4. 存入向量資料庫
                                                              ↑
使用者提問 → Embedding → 向量搜尋（找最相關的文件）────────────┘
                                    ↓
                        把相關文件 + 問題一起丟給 LLM → 生成答案
```

### RAG 解決的問題

| 問題 | RAG 怎麼解決 |
|------|-------------|
| 知識過時 | 更新文件庫就好，不用重新訓練 |
| 幻覺 | 有文件依據，可追溯來源 |
| 領域知識 | 直接餵入公司內部文件 |
| 隱私 | 資料不需要進入模型訓練 |

### RAG vs Fine-tuning

| 面向 | RAG | Fine-tuning |
|------|-----|-------------|
| 知識更新 | 即時（改文件庫） | 要重新訓練 |
| 成本 | 低 | 高（要 GPU） |
| 幻覺控制 | 有來源可查 | 較難控制 |
| 適用場景 | 知識密集型問答 | 改變模型行為/風格 |

## 3.1 Fine-tuning 方法

### 方法比較表

| 方法 | 訓練比例 | 白話說明 | 資源需求 |
|------|---------|---------|---------|
| **Full Fine-tuning** | 100% | 全部重練 | 極高 |
| **LoRA** | ~0.1% | 凍結原始，只練小旁路 | 低 |
| **QLoRA** | ~0.1% | 先量化再 LoRA | 更低 |
| **Adapter** | ~1-5% | 層間插入小模組 | 低 |
| **Prefix Tuning** | <0.1% | 學習輸入前綴 | 低 |
| **Prompt Tuning** | <0.01% | 學習軟提示向量 | 最低 |

### LoRA 原理（★★★ 必考）

**核心公式**：$W' = W + \Delta W = W + BA$

| 符號 | 意思 |
|------|------|
| W | 原始權重（凍結不動） |
| B | 低秩矩陣 (d × r) |
| A | 低秩矩陣 (r × k) |
| r | Rank，通常 8~64（越小越省） |

**白話**：原始模型是一堵很大的牆（百億參數），LoRA 只在牆邊貼一條小紙條（幾百萬參數）。訓練時只更新紙條，牆不動。

**優點**：
- 省記憶體（只訓練 0.1% 參數）
- 可同時存多個 LoRA（一個基礎模型 + 多個任務）
- 效果接近全量微調

### QLoRA

LoRA + 量化：先把模型壓縮到 4-bit（省記憶體），再做 LoRA 微調。  
→ 單張 24GB GPU 就能微調 7B 模型。

---

## 3.2 模型評估指標

### 核心指標

| 指標 | 公式/說明 | 白話 | 用途 |
|------|----------|------|------|
| **BLEU** | n-gram **精確率** | 「我生成的詞，有多少出現在標準答案裡」 | 機器翻譯 |
| **ROUGE** | n-gram **召回率** | 「標準答案的詞，有多少被我涵蓋到」 | 文字摘要 |
| **Perplexity** | $PPL = \exp(-\frac{1}{N}\sum\log P(w_i))$ | 模型多「驚訝」→ 越低越好 | 語言模型品質 |
| **F1-Score** | $\frac{2 \times P \times R}{P + R}$ | 精確率和召回率的平衡分數 | 分類任務 |

> 🚨 **考試陷阱**：  
> - BLEU 高 ≠ 字彙量增加（只代表更像參考文本）  
> - ROUGE 重視「別漏掉重點」（召回率導向）  
> - BLEU 重視「別說錯話」（精確率導向）

### LLM 評估基準

| 基準測試 | 測什麼 |
|---------|--------|
| MMLU | 57 個學科的知識測驗 |
| HumanEval | Python 程式碼正確性 |
| GSM8K | 小學數學推理 |
| TruthfulQA | 是否會生成假資訊 |
| MT-Bench | 多輪對話品質 |

## 3.3 量化（Quantization）

**白話**：把模型的「精度」降低（像圖片從高畫質壓到低畫質），換取更小的體積和更快的速度。

### 精度比較

| 精度 | 每個參數佔用 | 7B 模型大小 |
|------|------------|------------|
| FP32 | 4 bytes | ~28 GB |
| FP16 | 2 bytes | ~14 GB |
| INT8 | 1 byte | ~7 GB |
| INT4 | 0.5 bytes | ~3.5 GB |

### 量化方法

| 方法 | 特點 |
|------|------|
| GPTQ | 後訓練量化，GPU 友好 |
| AWQ | 保護重要權重，品質較好 |
| bitsandbytes | 和 HuggingFace 整合最好 |

> ⚡ **考試重點**：量化是為了**省記憶體和加速推論**，不是為了提升準確度！

## 3.4 訓練實務

### 多 GPU 訓練

| 方式 | 白話說明 | 適用場景 |
|------|---------|---------|
| **Data Parallelism** | 每張 GPU 跑不同資料 | 模型放得下單 GPU |
| **Tensor Parallelism** | 一個矩陣切開分給多 GPU | 模型太大放不下 |
| **Pipeline Parallelism** | 不同層放不同 GPU | 模型很深 |
| **All-Reduce** | 同步所有 GPU 的梯度 | 配合 Data Parallelism |
| **Mixed Precision** | FP16 計算 + FP32 累加 | 加速 + 省記憶體 |

### 其他實務概念

| 概念 | 說明 |
|------|------|
| **A/B 測試** | 兩個模型各服務 50% 流量，比較哪個好 |
| **災難性遺忘** | 微調後忘了原本的能力 → LoRA、資料混合可緩解 |
| **Beam Search** | 同時探索多條生成路徑，選最好的 |
| **Gradient Checkpointing** | 用計算換記憶體（省空間但慢一點） |

## 易錯陷阱

1. BLEU 高 ≠ 字彙量增加（只代表接近參考文本）
2. Triton = 推論伺服器；TensorRT = 加速引擎（別搞混）
3. 量化是省記憶體和加速，**不是提升準確度**
4. A/B 測試要 **50/50** 平均分配流量
5. EDA 是微調前必備步驟
6. 跨框架模型互通首選 **ONNX**
7. Base Command 是 DGX 的作業系統
8. 災難性遺忘可用 LoRA 緩解
9. Transformer 用 **Layer Norm**（不是 Batch Norm）
10. Query 負責「尋找」，Value 負責「提供資訊」

## 概念對比速查

| A vs B | A | B |
|--------|---|---|
| Encoder vs Decoder | 雙向注意力、理解 | 單向注意力、生成 |
| LoRA vs Full FT | 0.1% 參數、快 | 100% 參數、效果最好 |
| RAG vs Fine-tuning | 動態知識、免訓練 | 固定知識、改變行為 |
| RLHF vs DPO | 需獎勵模型 | 不需要、更簡單 |
| BLEU vs ROUGE | 精確率（翻譯） | 召回率（摘要） |
| Temperature 0 vs 1 | 確定性 | 高隨機性 |
| BPE vs WordPiece | 頻率合併 | 似然度合併 |
| vLLM vs Triton | LLM 專用推論 | 通用模型伺服器 |
