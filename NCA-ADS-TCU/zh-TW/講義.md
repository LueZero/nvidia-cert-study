### 1.1 NVIDIA cuDF 與 pandas 深度比較

**cuDF 是什麼？**
- NVIDIA RAPIDS 生態系的 GPU 加速 DataFrame 函式庫
- API 相容 pandas（幾乎可以無縫替換）
- 在 GPU 上執行資料操作，速度比 pandas 快 10-100 倍
- 底層使用 Apache Arrow 列式記憶體格式

**cuDF vs pandas 詳細比較：**

| 面向 | pandas | cuDF |
|------|--------|------|
| 執行環境 | CPU | GPU (CUDA) |
| 記憶體 | 系統 RAM | GPU VRAM (HBM) |
| 適合資料量 | < 10GB | 數百 GB（配合 Dask-cuDF） |
| 速度 | 基準 | 10-100x 加速 |
| API 相容性 | — | 95%+ 相容 pandas |
| 底層格式 | NumPy arrays | Apache Arrow |
| 字串處理 | object dtype | nvStrings (GPU) |

**cuDF 常用操作完整範例：**

### 1.2 資料整合與聯結（Data Integration & Joining）

**五種 Join 類型詳解：**

| Join 類型 | 說明 | SQL 等效 | 結果行數 |
|-----------|------|----------|----------|
| **Inner Join** | 只保留兩邊都有匹配鍵的行 | INNER JOIN | ≤ min(A, B) |
| **Left Join** | 保留左表所有行，右表無匹配填 NaN | LEFT OUTER JOIN | = A |
| **Right Join** | 保留右表所有行，左表無匹配填 NaN | RIGHT OUTER JOIN | = B |
| **Outer Join** | 保留兩邊所有行，無匹配填 NaN | FULL OUTER JOIN | ≤ A + B |
| **Cross Join** | 笛卡爾積（每行配每行） | CROSS JOIN | A × B |

**合併操作程式碼：**
```python
# Inner Join - 最常用
result = cudf.merge(orders, customers, on='customer_id', how='inner')

# Left Join - 保留所有訂單
result = cudf.merge(orders, customers, on='customer_id', how='left')

# 多鍵聯結
result = cudf.merge(df1, df2, on=['key1', 'key2'], how='inner')

# 不同欄名的聯結
result = cudf.merge(df1, df2, left_on='emp_id', right_on='employee_id')

# concat 堆疊
all_data = cudf.concat([jan_data, feb_data, mar_data], ignore_index=True)
```

**資料整合最佳實踐：**
- 聯結前檢查鍵值的唯一性和完整性
- 注意 NaN 值不會匹配（NaN ≠ NaN）
- 大表 join 小表效率較高
- 使用 `.merge_asof()` 處理時間序列的近似匹配

**異常值偵測方法：**

| 方法 | 公式/說明 | 適用 |
|------|-----------|------|
| **IQR** | < Q1-1.5×IQR 或 > Q3+1.5×IQR | 非常態分佈 |
| **Z-score** | \|z\| > 3 視為異常 | 常態分佈 |
| **Modified Z-score** | 使用中位數和 MAD | 有極端值時 |
| **Isolation Forest** | ML 方法 | 高維資料 |

```python
# IQR 方法
Q1 = df['value'].quantile(0.25)
Q3 = df['value'].quantile(0.75)
IQR = Q3 - Q1
lower_bound = Q1 - 1.5 * IQR
upper_bound = Q3 + 1.5 * IQR
outliers = df[(df['value'] < lower_bound) | (df['value'] > upper_bound)]

# Z-score 方法
from scipy import stats
z_scores = stats.zscore(df['value'])
outliers = df[abs(z_scores) > 3]
```

### 1.5 特徵工程（Feature Engineering）

**數值特徵轉換：**

| 方法 | 公式 | 效果 | 適用 |
|------|------|------|------|
| **標準化 (Z-score)** | $z = \frac{x - \mu}{\sigma}$ | 均值=0, 標準差=1 | SVM, KNN, 線性模型 |
| **Min-Max 正規化** | $x' = \frac{x - x_{min}}{x_{max} - x_{min}}$ | 縮放至 [0,1] | 神經網路 |
| **Robust Scaling** | $x' = \frac{x - Q2}{Q3 - Q1}$ | 抗異常值 | 有異常值時 |
| **對數轉換** | $x' = \log(x + 1)$ | 壓縮右偏態 | 收入、價格 |
| **平方根轉換** | $x' = \sqrt{x}$ | 輕度壓縮 | 計數資料 |
| **Box-Cox 轉換** | 自動找最佳 λ | 使分佈接近常態 | 任意偏態 |

```python
from cuml.preprocessing import StandardScaler, MinMaxScaler, RobustScaler
```

**類別特徵編碼：**

| 編碼方式 | 說明 | 優點 | 缺點 | 適用 |
|----------|------|------|------|------|
| **Label Encoding** | 類別 → 整數 | 簡單、不增加維度 | 引入順序關係 | 有序類別、樹模型 |
| **One-Hot Encoding** | 每類別一個二元欄位 | 無順序假設 | 高基數維度爆炸 | 無序、少量類別 |
| **Target Encoding** | 類別 → 目標均值 | 適合高基數 | 過擬合風險 | 高基數+樹模型 |
| **Frequency Encoding** | 類別 → 出現頻率 | 簡單有效 | 不同類別可能同頻 | 頻率有意義時 |
| **Binary Encoding** | 類別 → 二進位 | 較少欄位 | 欄位間可能無意義 | 中等基數 |


### 1.6 處理類別不平衡（Class Imbalance）

**不平衡問題：** 當某類別樣本數遠少於其他類別（如欺詐偵測 1% vs 99%）

| 策略 | 方法 | 說明 |
|------|------|------|
| **資料層面** | Random Oversampling | 隨機複製少數類別 |

| | **SMOTE** | 在少數類別近鄰間插值生成合成樣本 |
| | ADASYN | 自適應合成，在困難區域生成更多樣本 |
| **演算法層面** | Class Weight | 調整損失函數對少數類別的權重 |
| | Cost-Sensitive Learning | 不同錯誤類型有不同代價 |
| **評估層面** | 使用 F1/AUC | 避免只看 Accuracy |
| | Precision-Recall Curve | 比 ROC 更適合不平衡資料 |

### 2.4 模型評估指標

**分類指標：**

| 指標 | 公式 | 說明 | 適合 |
|------|------|------|------|
| **Accuracy** | $\frac{TP+TN}{TP+TN+FP+FN}$ | 整體正確率 | 平衡資料 |
| **Precision** | $\frac{TP}{TP+FP}$ | 預測正例的準確率 | 假陽性代價高 |
| **Recall (Sensitivity)** | $\frac{TP}{TP+FN}$ | 實際正例被找到的比率 | 假陰性代價高 |
| **Specificity** | $\frac{TN}{TN+FP}$ | 實際負例被正確識別的比率 | 雙面評估 |
| **F1 Score** | $\frac{2 \times P \times R}{P + R}$ | Precision 和 Recall 的調和平均 | 不平衡資料 |
| **AUC-ROC** | ROC 曲線下面積 | 分類器整體區分能力 | 閾值選擇 |
| **Log Loss** | $-\frac{1}{N}\sum[y\log(p)+(1-y)\log(1-p)]$ | 機率預測的品質 | 機率校準 |

**混淆矩陣詳解：**
```
                    預測正 (Positive)    預測負 (Negative)
實際正 (Positive)  │     TP           │      FN          │
                   │  True Positive   │  False Negative  │
                   │  正確找到         │  遺漏（漏報）     │
─────────────────────────────────────────────────────────
實際負 (Negative)  │     FP           │      TN          │
                   │  False Positive  │  True Negative   │
                   │  誤報             │  正確排除        │
```

**迴歸指標：**

| 指標 | 公式 | 說明 | 用途與應用 |
|------|------|------|-----------|
| **MAE** | $\frac{1}{n}\sum\lvert y_i - \hat{y}_i \rvert$ | 平均絕對誤差 | 對異常值穩健，適合需求預測、溫度預測等實際業務場景 |
| **MSE** | $\frac{1}{n}\sum(y_i - \hat{y}_i)^2$ | 均方誤差（對大誤差敏感） | 機器學習訓練標準損失函數，大誤差代價高的場景（金融風控） |
| **RMSE** | $\sqrt{MSE}$ | 均方根誤差（同單位） | 結果可直接與原始數據比較，回報模型預測偏差量級 |
| **R²** | $1 - \frac{SS_{res}}{SS_{tot}}$ | 解釋變異比例（0-1） | 衡量模型解釋力，越接近 1 越好；常用於比較不同模型 |
| **Adjusted R²** | 調整後的 R² | 考慮特徵數量 | 多特徵模型比較，懲罰不必要的特徵加入 |

### 2.6 交叉驗證（Cross-Validation）

**K-Fold CV：**
```
K=5 時：
Fold 1: [TEST ] [Train] [Train] [Train] [Train]
Fold 2: [Train] [TEST ] [Train] [Train] [Train]
Fold 3: [Train] [Train] [TEST ] [Train] [Train]
Fold 4: [Train] [Train] [Train] [TEST ] [Train]
Fold 5: [Train] [Train] [Train] [Train] [TEST ]
→ 最終分數 = 5 次分數的平均值 ± 標準差
```

**CV 變體：**

| 方法 | 說明 | 適合 |
|------|------|------|
| **K-Fold** | 標準 K 折 | 一般情況 |
| **Stratified K-Fold** | 保持類別比例 | 不平衡分類 |
| **TimeSeriesSplit** | 時間順序分割 | 時間序列 |
| **Leave-One-Out** | 每次留一個測試 | 極小資料集 |
| **Repeated K-Fold** | 重複多次 K-Fold | 更穩定的估計 |

```python
from cuml.model_selection import cross_val_score, StratifiedKFold

# Stratified K-Fold

print(f"F1: {scores.mean():.4f} ± {scores.std():.4f}")
```

### 3.2 過擬合與欠擬合

| 問題 | 徵兆 | 原因 | 解決方法 |
|------|------|------|----------|
| **過擬合** | 訓練損失低、驗證損失高 | 模型太複雜、資料少 | 正則化、Dropout、增加資料、Early Stopping、簡化模型 |
| **欠擬合** | 訓練和驗證損失都高 | 模型太簡單 | 增加模型複雜度、更多特徵、更長訓練、減少正則化 |
| **良好擬合** | 訓練和驗證損失都低且接近 | 適當平衡 | 維持現狀 |

**正則化技術：**

| 技術 | 公式/說明 | 效果 | 應用場景 |
|------|-----------|------|---------|
| **L1 (Lasso)** | $\lambda\sum\lvert w_i \rvert$ | 稀疏化，自動特徵選擇 | 高維特徵選擇（基因組學、文本特徵） |
| **L2 (Ridge)** | $\lambda\sum w_i^2$ | 權重衰減，防止極大權重 | 多重共線性迴歸、神經網路 weight decay |
| **ElasticNet** | L1 + L2 混合 | 兩者優點結合 | 特徵多且部分相關時 |
| **Dropout** | 隨機停用節點 | 防止神經網路過擬合 | 全連接層、Transformer（通常 p=0.1） |
| **Early Stopping** | 驗證集效能停止改善時停訓 | 通用 | 所有迭代訓練模型 |
| **資料擴增** | 增加訓練資料多樣性 | 從根本解決 | 圖像（翻轉/旋轉）、文本（同義詞替換） |

### 4.1 探索性資料分析（EDA）與描述統計

**集中趨勢：**
| 統計量 | 說明 | 敏感度 |
|--------|------|--------|
| **Mean（平均值）** | 所有值的算術平均 | 受異常值影響大 |
| **Median（中位數）** | 排序後的中間值 | 不受異常值影響 |
| **Mode（眾數）** | 出現最頻繁的值 | 適合類別資料 |
| **Trimmed Mean** | 去掉極端值後的平均 | 折衷方案 |

**離散程度：**
| 統計量 | 公式 | 說明 |
|--------|------|------|
| **Range** | max - min | 全距 |
| **Variance（變異數）** | $\sigma^2 = \frac{1}{n}\sum(x_i - \mu)^2$ | 平均偏差的平方 |
| **Std Dev（標準差）** | $\sigma = \sqrt{Variance}$ | 同單位的離散度 |
| **IQR** | Q3 - Q1 | 中間50%的範圍 |

**分佈形狀：**

|--------|------|------|
| **Skewness（偏態）** | 分佈的對稱性 | 0=對稱, >0 右偏, <0 左偏 |
| **Kurtosis（峰態）** | 尾部的厚度 | 3=常態, >3 厚尾, <3 薄尾 |

**分位數：**
- Q1 (25th percentile)：第一四分位數
- Q2 (50th) = Median：中位數
- Q3 (75th)：第三四分位數
- IQR = Q3 - Q1：四分位距

### 4.3 假設檢定與統計顯著性

**假設檢定流程：**
```
1. 設立假設：H₀（虛無假設）vs H₁（對立假設）
2. 選擇顯著水準：α = 0.05（通常）
3. 計算檢定統計量
4. 計算 p-value
5. 做決定：p < α → 拒絕 H₀
```

**核心概念：**

| 概念 | 說明 |
|------|------|
| **H₀（虛無假設）** | 假設沒有效果/差異（預設立場） |
| **H₁（對立假設）** | 假設有效果/差異（要證明的） |
| **p-value** | 在 H₀ 為真時，觀察到當前或更極端結果的機率 |
| **α（顯著水準）** | 拒絕 H₀ 的門檻（通常 0.05） |
| **Type I Error（α）** | 錯誤拒絕 H₀（偽陽性） |
| **Type II Error（β）** | 未能拒絕錯誤的 H₀（偽陰性） |
| **Power（1-β）** | 正確拒絕錯誤 H₀ 的能力 |
| **Effect Size** | 效果的實際大小 |

**常用統計檢定：**

| 檢定 | 用途 | 假設 |
|------|------|------|
| **t-test** | 兩組均值差異 | 常態分佈、等變異 |
| **Paired t-test** | 配對樣本均值差異 | 配對、常態差值 |
| **ANOVA** | 多組均值差異 | 常態、等變異 |
| **Chi-square** | 類別變數獨立性 | 期望頻率 > 5 |
| **Mann-Whitney U** | 兩組中位數差異 | 非常態 |
| **Pearson r** | 線性相關性 | 連續、常態 |
| **Spearman ρ** | 單調相關性 | 有序/非線性 |

**相關係數解讀：**
| 範圍 | 強度 |
|------|------|
| 0.0 - 0.2 | 極弱 |
| 0.2 - 0.4 | 弱 |
| 0.4 - 0.6 | 中等 |
| 0.6 - 0.8 | 強 |
| 0.8 - 1.0 | 極強 |

### 4.4 解讀模式、趨勢與關係

**趨勢類型：**
- **上升趨勢**：隨時間增長
- **下降趨勢**：隨時間減少
- **週期性**：固定週期重複
- **季節性**：特定季節/時段的模式
- **無趨勢（平穩）**：圍繞均值波動

**散佈圖中的關係：**
- **正相關**：一個增加另一個也增加
- **負相關**：一個增加另一個減少
- **無相關**：無明顯關係
- **非線性**：曲線關係（指數、多項式）

### 5.2 GPU 加速核心概念

**GPU 架構（NVIDIA）：**

| 概念 | 說明 |
|------|------|
| **CUDA Core** | 基本計算單元，數千個同時工作 |
| **Streaming Multiprocessor (SM)** | 包含多個 CUDA Core 的處理器 |
| **Warp** | 32 個 thread 為一組同步執行 |
| **Thread Block** | 一組 thread，共享 shared memory |
| **Grid** | 所有 thread block 的集合 |
| **HBM (High Bandwidth Memory)** | GPU 記憶體，TB/s 級頻寬 |
| **L1/L2 Cache** | GPU 上的快取 |

**為什麼 GPU 加速資料科學？**
1. **大規模平行**：數千核心同時處理不同資料
2. **高記憶體頻寬**：HBM2e 可達 2 TB/s（CPU DDR5 ~50 GB/s）
3. **向量化操作**：矩陣/向量運算天生適合 GPU
4. **批次處理**：同一操作應用於大量資料

---

### 5.3 CPU vs GPU 工作負載選擇

| 適合 GPU | 適合 CPU |
|----------|----------|
| 大資料集（> 100MB） | 小資料集（< 10MB） |
| 向量化/矩陣運算 | 複雜分支邏輯 |
| 批次相同操作 | 序列性任務 |
| 高度平行化 | I/O 密集型 |
| 數學密集型計算 | 字串/正則處理 |
| 訓練 ML/DL 模型 | 簡單的 if/else 邏輯 |

**何時 GPU 不划算：**
- 資料太小，GPU 啟動開銷 > 計算節省
- 需要頻繁 CPU↔GPU 資料搬移
- 演算法本質上是序列的
- GPU 記憶體不夠且無法使用 Dask-cuDF

### 5.4 記憶體傳輸最佳化

```
┌─────────────┐   PCIe Bus    ┌─────────────┐
│   CPU       │ ←───────────→ │    GPU      │
│  (Host)     │   ~64 GB/s    │  (Device)   │
│  System RAM │               │  HBM/VRAM   │
└─────────────┘               └─────────────┘
      ↑                              ↑
   瓶頸：PCIe 頻寬遠低於 GPU 記憶體頻寬
```

**最佳化策略：**
| 策略 | 說明 |
|------|------|
| **減少傳輸次數** | 盡量讓資料留在 GPU 上 |
| **批次傳輸** | 一次傳大塊資料，而非多次小量 |
| **非同步傳輸** | 傳輸和計算重疊 |
| **GPU Direct Storage** | GPU 直接讀取 NVMe，繞過 CPU |
| **Unified Memory** | 自動管理 CPU/GPU 記憶體遷移 |
| **RAPIDS Memory Manager (RMM)** | 預分配 GPU 記憶體池 |

```python
import rmm
# 使用記憶體池避免頻繁分配/釋放
rmm.reinitialize(pool_allocator=True, initial_pool_size=2**30)  # 1GB
```

**關鍵區別：**

### 7.3 圖形資料（Graph Data）與 cuGraph

**cuGraph** — RAPIDS 的 GPU 加速圖分析函式庫：

**圖的基本概念：**
| 概念 | 說明 |
|------|------|
| **節點（Node/Vertex）** | 圖中的實體 |
| **邊（Edge）** | 節點間的連接關係 |
| **有向圖** | 邊有方向（A→B ≠ B→A） |
| **無向圖** | 邊無方向（A-B = B-A） |
| **加權圖** | 邊有權重值 |
| **度（Degree）** | 節點的連接數 |
| **入度/出度** | 有向圖中的進/出連接數 |

**cuGraph 演算法：**

| 類別 | 演算法 | 用途 |
|------|--------|------|
| **中心性** | PageRank | 節點重要性排序 |
| | Betweenness Centrality | 橋接節點識別 |
| | Katz Centrality | 影響力衡量 |
| **社群偵測** | Louvain | 社群分割 |
| | Label Propagation | 快速社群發現 |
| **路徑** | BFS/DFS | 搜尋 |
| | SSSP | 單源最短路徑 |
| **連通性** | Connected Components | 找出連通子圖 |

```python
import cugraph
import cudf

# 建立圖
edges = cudf.DataFrame({
    'src': [0, 1, 2, 0, 3],
    'dst': [1, 2, 3, 2, 0],
    'weight': [1.0, 2.0, 1.5, 0.5, 3.0]
})
G = cugraph.Graph()
G.from_cudf_edgelist(edges, source='src', destination='dst', edge_attr='weight')

# PageRank
pagerank = cugraph.pagerank(G)
print(pagerank.sort_values('pagerank', ascending=False))

# 社群偵測 (Louvain)
parts, modularity = cugraph.louvain(G)

# BFS
bfs_result = cugraph.bfs(G, start=0)
```

## 📌 重點公式速查

| 公式 | 用途 | 應用場景 |
|------|------|---------|
| $z = \frac{x - \mu}{\sigma}$ | 標準化 (Z-score) | 線性模型、SVM、KNN 等對尺度敏感的演算法前處理 |
| $x' = \frac{x - x_{min}}{x_{max} - x_{min}}$ | Min-Max 正規化 | 神經網路輸入標準化，縮放至 [0,1] 範圍 |
| $Precision = \frac{TP}{TP+FP}$ | 精確率 | 假陽性代價高的場景（垃圾郵件分類、推薦系統） |
| $Recall = \frac{TP}{TP+FN}$ | 召回率 | 假陰性代價高的場景（疾病篩檢、欺詐偵測） |
| $F1 = \frac{2 \times P \times R}{P + R}$ | F1 分數 | 類別不平衡時的綜合評估指標 |
| $R^2 = 1 - \frac{SS_{res}}{SS_{tot}}$ | 決定係數 | 迴歸模型解釋力評估，1 為完美擬合 |
| $IQR = Q3 - Q1$ | 四分位距 | 異常值偵測（超出 Q1-1.5×IQR 或 Q3+1.5×IQR 為離群） |
| $MSE = \frac{1}{n}\sum(y_i - \hat{y}_i)^2$ | 均方誤差 | 迴歸模型訓練損失函數，懲罰大誤差 |
| $RMSE = \sqrt{MSE}$ | 均方根誤差 | 與原始數據同單位，直觀衡量預測偏差大小 |

## 📌 考試重點提示

1. **cuDF vs pandas**：知道 cuDF 是 GPU 加速的 pandas 替代品，API 幾乎相同
2. **tree_method='gpu_hist'**：XGBoost 啟用 GPU 的關鍵參數
3. **Parquet > CSV**：列式儲存、高壓縮、保留 Schema、GPU 讀寫快
4. **Dask-cuDF**：處理超過 GPU 記憶體的資料、延遲計算 + `.compute()`
5. **DBSCAN**：密度分群、不需指定群數、能偵測噪音
6. **時間序列不能隨機分割**：必須保持時間順序
7. **SMOTE**：在少數類別近鄰間插值生成合成樣本
8. **PCIe 瓶頸**：CPU↔GPU 傳輸是瓶頸，減少傳輸次數
9. **MLflow**：實驗追蹤 + 模型註冊 + 部署
10. **nvidia-smi**：檢查 GPU 狀態、驅動版本決定最高 CUDA 版本
