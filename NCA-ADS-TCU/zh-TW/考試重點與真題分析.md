## 📋 Domain 1: GPU-Accelerated Data Manipulation（23%）— 最重要！

### 1.1 cuDF — GPU DataFrame（★★★ 考試核心）

#### cuDF vs Pandas 對應
| Pandas | cuDF | 差異 |
|--------|------|------|
| `pd.DataFrame()` | `cudf.DataFrame()` | GPU 記憶體 |
| `pd.read_csv()` | `cudf.read_csv()` | GPU 加速讀取 |
| `df.groupby()` | `gdf.groupby()` | GPU 加速聚合 |
| `df.merge()` | `gdf.merge()` | GPU 加速 join |
| `df.sort_values()` | `gdf.sort_values()` | GPU 加速排序 |
| `pd.read_parquet()` | `cudf.read_parquet()` | GPU 直接讀取 |

#### cuDF 核心特性
| 特性 | 說明 | 考試重點 |
|------|------|----------|
| API 相容性 | 大部分與 Pandas 相同 | ★★★ 幾乎可直接替換 |
| 資料類型 | int, float, string, datetime, categorical | 支援 nullable |
| I/O 支援 | CSV, Parquet, ORC, JSON, Avro | Parquet 最佳效能 |
| 記憶體限制 | 受 GPU VRAM 限制 | 比系統 RAM 小 |
| String 操作 | `.str` accessor | GPU 加速字串處理 |
| Missing values | nullable 類型 | `<NA>` not NaN |

#### cuDF 常見操作考點
```python
import cudf

# 讀取資料
gdf = cudf.read_csv('data.csv')
gdf = cudf.read_parquet('data.parquet')  # 效能最佳

# 基本操作
gdf.head(), gdf.describe(), gdf.info()
gdf['col'].value_counts()
gdf.groupby('col').agg({'val': ['mean', 'sum']})
gdf.merge(other_gdf, on='key', how='left')

# 與 Pandas 互轉
pdf = gdf.to_pandas()  # GPU → CPU
gdf = cudf.from_pandas(pdf)  # CPU → GPU
```

### 1.2 cuDF-Pandas Accelerator Mode（新功能 ★★★）
```python
# 零修改加速！
%load_ext cudf.pandas
import pandas as pd  # 自動使用 GPU 加速

# 或環境變數
# RAPIDS_CUDF_PANDAS=1 python script.py
```
- 透明加速：不需修改 Pandas 代碼
- 自動 fallback：不支援的操作回到 CPU
- 考試新趨勢考點

### 1.3 Dask-cuDF（分散式 GPU DataFrame）
```python
import dask_cudf

# 讀取大於 GPU 記憶體的資料
ddf = dask_cudf.read_parquet('large_data/*.parquet')
result = ddf.groupby('key').sum().compute()
```
- 處理超出單張 GPU 記憶體的資料
- 懶執行（lazy evaluation）
- `.compute()` 觸發實際計算

### 2.2 XGBoost GPU（★★★ 必考）
```python
import xgboost as xgb

# GPU 加速 XGBoost
params = {
    'tree_method': 'gpu_hist',  # ★ GPU 加速關鍵參數
    'device': 'cuda',
    'objective': 'binary:logistic',
    'max_depth': 6,
    'learning_rate': 0.1
}

dtrain = xgb.DMatrix(X_train, label=y_train)
model = xgb.train(params, dtrain, num_boost_round=100)
```
- `tree_method='gpu_hist'` 是啟用 GPU 加速的關鍵
- 與 cuDF DataFrame 無縫整合
- 比 CPU 快 10-25x

## 📋 Domain 4: GPU-Accelerated Graph Analytics（13%）

### 4.1 cuGraph — GPU 圖分析（★★★）

#### 支援的圖演算法
| 類別 | 演算法 | 用途 |
|------|--------|------|
| 中心性 | PageRank | 節點重要性 |
| 中心性 | Betweenness Centrality | 橋接節點 |
| 中心性 | Katz Centrality | 影響力 |
| 社群偵測 | Louvain | 社群分割 |
| 社群偵測 | Leiden | 改進 Louvain |
| 最短路徑 | SSSP (BFS) | 單源最短路 |
| 連通性 | Connected Components | 連通分量 |
| 遍歷 | BFS | 廣度優先 |
| Link Prediction | Jaccard, Overlap | 連結預測 |
| 採樣 | Node2Vec | 圖嵌入 |

#### cuGraph 基本用法
```python
import cugraph
import cudf

# 建立圖
edges = cudf.DataFrame({
    'src': [0, 1, 2, 0],
    'dst': [1, 2, 3, 3],
    'weight': [1.0, 2.0, 1.0, 3.0]
})

G = cugraph.Graph()
G.from_cudf_edgelist(edges, source='src', destination='dst', edge_attr='weight')

# PageRank
pr = cugraph.pagerank(G)

# Louvain 社群偵測
parts, modularity = cugraph.louvain(G)

# 最短路徑
distances = cugraph.sssp(G, source=0)
```

### 4.2 圖的表示方式
| 方式 | 說明 | 適用 |
|------|------|------|
| CSR (Compressed Sparse Row) | 稀疏矩陣格式 | cuGraph 內部 |
| Edge List | 邊列表 | 輸入格式 |
| Adjacency Matrix | 鄰接矩陣 | 小圖 |
| Adjacency List | 鄰接表 | 通用 |

### 5.1 RAPIDS 生態系統全覽（★★★ 必背）
| 元件 | 功能 | 對標 |
|------|------|------|
| **cuDF** | DataFrame 操作 | Pandas |
| **cuML** | 機器學習 | Scikit-learn |
| **cuGraph** | 圖分析 | NetworkX |
| **cuSpatial** | 地理空間分析 | GeoPandas |

| **cuxfilter** | 資料視覺化 | Crossfilter |

| **NVTabular** | 表格特徵工程 | 自有 |
| **cuCIM** | 醫學影像 | OpenSlide |

### 5.2 典型工作流程
```
1. 資料載入 → cudf.read_parquet()
2. 資料清洗 → cuDF 操作（fillna, drop, filter）
3. EDA → cuDF + cuxfilter
4. 特徵工程 → cuDF + cuML preprocessing
5. 模型訓練 → cuML / XGBoost GPU
6. 模型評估 → cuML metrics
7. 部署 → Triton Inference Server
```

### 5.3 從 Pandas/Sklearn 遷移的關鍵差異
| 差異點 | CPU (Pandas/Sklearn) | GPU (RAPIDS) |
|--------|---------------------|--------------|
| 記憶體 | System RAM | GPU VRAM（較小） |
| 隨機數 | numpy.random | cupy.random（結果可能不同） |
| Index | 完整 Pandas Index | 部分支援 |
| Custom functions | apply() 靈活 | apply() 有限制 |
| Data transfer | 無需 | CPU↔GPU 有成本 |

## 📋 Domain 6: End-to-End GPU-Accelerated Pipelines（10%）

### 6.1 完整管線設計（★★★）
```python
import cudf
from cuml import train_test_split
from cuml.ensemble import RandomForestClassifier
from cuml.metrics import accuracy_score

# 1. 讀取
df = cudf.read_parquet('data.parquet')

# 2. 預處理
df = df.dropna()
df['category'] = df['category'].astype('category').cat.codes

# 3. 分割
X = df.drop('target', axis=1)
y = df['target']
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2)

# 4. 訓練
model = RandomForestClassifier(n_estimators=100)
model.fit(X_train, y_train)

# 5. 評估
preds = model.predict(X_test)
acc = accuracy_score(y_test, preds)
```

### 6.2 GPU 管線最佳實踐
| 原則 | 說明 |
|------|------|
| 減少 CPU↔GPU 傳輸 | 盡量保持資料在 GPU |
| 使用 Parquet | 比 CSV 快很多 |
| 批次處理 | 分批處理超大資料 |
| 管線串聯 | cuDF → cuML 零拷貝 |
| Memory-aware | 監控 GPU 記憶體使用 |
