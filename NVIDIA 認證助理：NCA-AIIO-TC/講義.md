#### 詳細比較表

| 面向 | AI | ML | DL |
|------|-----|-----|-----|
| **定義** | 使機器展現智能行為的廣泛科學 | 從資料中自動學習規則的 AI 子集 | 使用多層神經網路的 ML 子集 |
| **方法** | 規則系統、搜索、推理 | 決策樹、SVM、迴歸 | CNN、RNN、Transformer |
| **資料量** | 可不需要資料 | 需要結構化資料 | 需要大量資料（百萬+） |
| **特徵工程** | 人工定義 | 人工提取特徵 | 自動學習特徵 |
| **運算需求** | 低 | 中 | 極高（GPU 必需） |
| **代表應用** | 專家系統、規則引擎 | 垃圾郵件過濾、信用評分 | 影像辨識、NLP、LLM |

#### 學習範式分類

| 學習方式 | 說明 | 範例 |
|----------|------|------|
| **Supervised Learning（監督式學習）** | 有標註資料，學習輸入→輸出的映射 | 圖片分類、語音辨識 |
| **Unsupervised Learning（非監督式學習）** | 無標註資料，學習資料結構/模式 | 聚類、降維、異常偵測 |
| **Reinforcement Learning（強化學習）** | Agent 在環境中透過獎勵學習 | 遊戲 AI、機器人控制 |
| **Self-Supervised Learning（自監督學習）** | 從資料本身產生標籤 | GPT（預測下一個 token） |

#### 完整對比表

| 特性 | CPU | GPU |
|------|-----|-----|
| **核心數量** | 8-128 個大核心 | 數千個 CUDA 核心 + Tensor 核心 |
| **設計理念** | 延遲最佳化（Latency-optimized） | 吞吐量最佳化（Throughput-optimized） |
| **時脈頻率** | 3-5 GHz | 1-2 GHz |
| **記憶體** | DDR5 系統 RAM（~100 GB/s） | HBM3/HBM3e（3+ TB/s） |
| **快取** | 大型多級快取（L1/L2/L3） | 小型快取，重視頻寬 |
| **控制流** | 強大的分支預測和亂序執行 | 簡單控制，大量並行 |
| **適合工作** | 序列邏輯、作業系統、I/O | 矩陣運算、向量計算 |
| **典型應用** | 網頁伺服器、資料庫、控制程式 | AI 訓練/推論、科學計算 |
| **功耗** | 65-350W（TDP） | 300-700W（TDP） |
| **程式設計** | C/C++、Python、Java 等 | CUDA、OpenCL |

#### NVIDIA GPU 核心類型

| 核心類型 | 功能 | 典型運算 |
|----------|------|----------|
| **CUDA Core** | 通用平行運算 | FP32/FP64 浮點數運算 |
| **Tensor Core** | 矩陣乘法加法（MMA） | AI 訓練/推論加速（FP16/FP8/INT8） |
| **RT Core** | 光線追蹤加速 | 即時光線追蹤渲染 |

> **關鍵**：深度學習的核心運算是矩陣乘法（Matrix Multiplication），GPU 的大量 Tensor Core 天然適合此任務。

### 1.4 Training vs Inference 架構比較

#### 完整差異對照

| 面向 | Training（訓練） | Inference（推論） |
|------|------------------|------------------|
| **目標** | 從資料學習最佳模型參數 | 使用已訓練模型即時預測 |
| **最佳化重點** | 高吞吐量（Throughput） | 低延遲（Latency） |
| **運算規模** | 數天～數週，數百/數千 GPU | 毫秒～秒，1-少數 GPU |
| **Batch Size** | 大（32-4096+） | 小（1-32）或即時 |
| **精度需求** | FP32 / 混合精度（FP16+FP32） | FP16 / INT8 / FP8 / INT4（量化） |
| **記憶體需求** | 極大（模型+梯度+優化器狀態） | 相對小（僅模型權重） |
| **GPU 間通訊** | 極高（AllReduce 梯度同步） | 低到中 |
| **適合 GPU** | H100/H200 SXM、A100 | L4、L40S、T4、H100 NVL |
| **網路需求** | 高頻寬低延遲（InfiniBand） | 一般乙太網即可 |
| **軟體工具** | PyTorch、Megatron-LM、DeepSpeed | TensorRT、Triton Inference Server |

### 1.8 CUDA 平行運算平台

#### CUDA 核心概念

```
                    CUDA 程式執行模型
    
    Host (CPU)                    Device (GPU)
    ┌──────────┐                  ┌────────────────────────┐
    │          │   kernel >>>     │  Grid                  │
    │  main()  │ ───────────────► │  ┌──────┐ ┌──────┐    │
    │          │                  │  │Block0│ │Block1│    │
    │          │                  │  │┌─┬─┬─┐│ │┌─┬─┬─┐│   │
    │          │                  │  ││T│T│T││ ││T│T│T││   │
    │          │                  │  │└─┴─┴─┘│ │└─┴─┴─┘│   │
    │          │                  │  └──────┘ └──────┘    │
    │          │  ◄────────────── │  ...                   │
    └──────────┘   結果回傳       └────────────────────────┘
```

**CUDA 重要概念：**
- **Thread**：最小執行單元
- **Block**：一組 Threads，共享 Shared Memory
- **Grid**：一組 Blocks，構成完整 kernel
- **Warp**：32 個 Threads 同步執行（SIMT）

**考試重點：**
- CUDA 允許開發者用 C/C++、Python、Fortran 等常見語言撰寫程式
- 透過 extensions（擴展語法）表達平行運算
- 是 NVIDIA GPU 生態系統的基礎

### 2.6 網路需求與協定

#### AI 工作負載網路需求

| 需求 | 原因 | 解決方案 |
|------|------|----------|
| **超低延遲** | 梯度同步需即時完成，否則 GPU 閒置等待 | InfiniBand、RDMA |
| **超高頻寬** | 數十億參數的模型梯度需同步 | NDR 400Gb/s、XDR 800Gb/s |
| **RDMA** | 繞過 OS/CPU 直接存取遠端記憶體 | InfiniBand native、RoCE v2 |
| **零丟包** | 訓練任務容不得封包遺失 | 無損網路、PFC、ECN |
| **Collective Operations** | AllReduce、AllGather 等集合通訊 | NCCL、SHARP |

#### RDMA（Remote Direct Memory Access）

```
傳統網路通訊：                     RDMA：
┌──────┐                          ┌──────┐
│ App  │                          │ App  │
│  ↓   │                          │  ↓   │ ← 繞過 OS
│  OS  │                          │ RDMA │
│  ↓   │                          │ NIC  │
│ TCP  │                          └──┬───┘
│  ↓   │                             │
│ NIC  │                             │ 直接 DMA
└──┬───┘                             │
   │  多次記憶體拷貝                    │ 零拷貝
   ↓                                 ↓
```

**RDMA 優勢：**
- 零拷貝（Zero-copy）
- 極低延遲（< 1 μs）
- CPU 零負擔（CPU offload）
- 高吞吐量

#### 資料中心網路協定

| 協定/技術 | 說明 | 用途 |
|-----------|------|------|
| **InfiniBand** | 高效能低延遲叢集互連（RDMA native） | AI 訓練首選 |
| **RoCE v2** | RDMA over Converged Ethernet（UDP 封裝） | 乙太網上的 RDMA |
| **Ethernet** | 通用網路協定 | 管理網路、一般流量 |
| **PFC（Priority Flow Control）** | 乙太網無損傳輸 | RoCE 環境防丟包 |
| **ECN（Explicit Congestion Notification）** | 擁塞通知 | 流量控制 |
| **BGP** | 邊界閘道協定 | 路由選擇 |
| **VXLAN** | 虛擬擴展 LAN | 網路虛擬化 |

#### InfiniBand 速度演進

| 世代 | 單通道速率 | 4x 速率 | NVIDIA 交換器 | 年份 |

| **效能可預測性** | 高（固定資源） | 中（共享資源） |
| **靈活性** | 固定切割，需重置才能改 | 動態分配 |
| **授權** | 免費（GPU 硬體內建） | 需 vGPU 軟體授權 |

#### 容器化 GPU 工作負載

##### NVIDIA Container Toolkit

```bash
# 安裝 NVIDIA Container Toolkit
$ distribution=$(. /etc/os-release;echo $ID$VERSION_ID)

    sudo apt-key add -
$ sudo apt-get install nvidia-container-toolkit

# 配置 Docker Runtime
$ sudo nvidia-ctk runtime configure --runtime=docker
$ sudo systemctl restart docker

# 運行 GPU 容器
$ docker run --gpus all nvidia/cuda:12.2.0-base-ubuntu22.04 nvidia-smi

# 指定 GPU
$ docker run --gpus '"device=0,1"' my-training-image python train.py

# 使用 MIG
$ docker run --gpus '"device=MIG-..."' my-inference-image
```

### 架構差異速記

| 比較 | A（特性） | B（特性） |
|------|-----------|-----------|
| Training vs Inference | 高吞吐量、FP32/FP16、多 GPU | 低延遲、INT8/FP8、少 GPU |

| NVLink vs InfiniBand | 節點內（Scale Up） | 跨節點（Scale Out） |
| MIG vs vGPU | 硬體分割、無需 Hypervisor | 軟體虛擬化、需 Hypervisor |
| InfiniBand vs RoCE | 原生 RDMA、最低延遲 | 乙太網上 RDMA、成本較低 |

| GPU vs CPU | 大量核心、吞吐量優化 | 少量大核心、延遲優化 |

### 考試常見陷阱

| 陷阱 | 正確理解 |
|------|----------|
| ❌ Moore's Law 驅動 AI 進步 | ✅ GPU 運算力和大量資料才是主因 |
| ❌ Training 使用 INT8 | ✅ Training 用 FP32/FP16；Inference 才用 INT8/FP8 |
| ❌ NVLink 用於跨節點 | ✅ NVLink 是節點內；InfiniBand 是跨節點 |
| ❌ MIG 需要 Hypervisor | ✅ MIG 是硬體分割，不需要 Hypervisor |
| ❌ vGPU 和 MIG 相同 | ✅ vGPU 是軟體虛擬化；MIG 是硬體隔離 |
| ❌ CUDA 只支援 C 語言 | ✅ CUDA 支援 C/C++、Python、Fortran 等 |
| ❌ DPU 取代 GPU | ✅ DPU 是第三顆處理器，卸載基礎設施任務 |
| ❌ Merlin 是 LLM 框架 | ✅ Merlin 是推薦系統框架；NeMo 才是 LLM |
| ❌ RoCE 等於 InfiniBand | ✅ RoCE 是乙太網上的 RDMA，效能低於 InfiniBand |
| ❌ PCIe Gen5 比 NVLink 快 | ✅ NVLink 是 PCIe Gen5 的 7 倍 |

### 考試策略

1. **Domain 2（40%）是重中之重** — 至少掌握 GPU 架構、網路技術、DGX 系統規格
2. **記住關鍵數字** — H100 規格、NVLink 頻寬、InfiniBand 速率
3. **理解配對關係** — 每個 NVIDIA 框架對應什麼用途
4. **Training vs Inference** — 確保能區分所有面向的差異
5. **時間管理** — 50 題 / 60 分鐘 = 每題 1.2 分鐘，不要在單題卡太久
6. **排除法** — 很多題目有明顯錯誤選項可先排除
