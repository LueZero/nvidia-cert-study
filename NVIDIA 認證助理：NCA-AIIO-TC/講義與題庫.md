## 📘 領域 1：Essential AI Knowledge（基礎 AI 知識）— 38%

### 1.1 AI、ML、DL 的區分

| 概念 | 定義 | 關係 |
|------|------|------|
| **AI（人工智慧）** | 讓機器模擬人類智能行為的廣泛領域 | 最大的集合 |
| **ML（機器學習）** | AI 的子集，透過資料學習模式而非明確程式設計 | AI ⊃ ML |
| **DL（深度學習）** | ML 的子集，使用多層神經網路進行學習 | ML ⊃ DL |

- **傳統程式設計**：輸入資料 + 規則 → 輸出結果
- **機器學習**：輸入資料 + 預期結果 → 學習規則
- **深度學習特點**：自動特徵提取、需要大量資料、需要 GPU 加速

### 1.2 AI 快速進步的因素

1. **資料爆炸**：網際網路、IoT、社群媒體產生的海量資料
2. **運算能力**：GPU 平行運算能力的指數成長（NVIDIA GPU）
3. **演算法進步**：Transformer、GAN、Diffusion Models 等突破
4. **開源生態**：PyTorch、TensorFlow 等框架降低門檻
5. **雲端運算**：按需取得大規模運算資源

### 1.3 GPU vs CPU 架構比較

| 特性 | CPU | GPU |
|------|-----|-----|
| 核心數 | 少（8-64 核） | 多（數千個 CUDA 核心） |
| 設計理念 | 低延遲、序列處理 | 高吞吐量、平行處理 |
| 適合工作 | 控制流程、分支邏輯 | 矩陣運算、資料平行 |
| 記憶體 | 系統 RAM（DDR） | 專用 VRAM（HBM） |
| 時脈 | 較高（3-5 GHz） | 較低（1-2 GHz） |

- **CUDA 核心**：NVIDIA GPU 的基本平行運算單元
- **Tensor 核心**：專為矩陣乘法加法（MMA）設計，大幅加速 DL 訓練與推論
- **HBM（High Bandwidth Memory）**：高頻寬記憶體，GPU 存取資料的關鍵

### 1.4 Training vs Inference 比較

| 面向 | Training（訓練） | Inference（推論） |
|------|------------------|------------------|
| 目的 | 從資料中學習模型參數 | 使用已訓練模型進行預測 |
| 運算需求 | 極高（數天～數週） | 相對低（毫秒～秒） |
| GPU 需求 | 多 GPU、大記憶體 | 可用較少 GPU |
| 精度 | 通常 FP32/混合精度 | 可用 FP16/INT8/INT4 |
| 批次大小 | 大批次 | 小批次/即時 |
| 頻寬需求 | 高（GPU 間通訊） | 較低 |

## 📘 領域 2：AI Infrastructure（AI 基礎設施）— 40%

### 2.1 GPU 硬體需求

**NVIDIA 資料中心 GPU 系列：**

| GPU | 架構 | HBM | 適用場景 |
|-----|------|-----|----------|
| **H100** | Hopper | 80GB HBM3 | 大型 LLM 訓練 |
| **H200** | Hopper | 141GB HBM3e | 超大模型訓練/推論 |
| **A100** | Ampere | 40/80GB HBM2e | 通用 AI 訓練/推論 |
| **L40S** | Ada Lovelace | 48GB GDDR6 | 推論和視覺化 |
| **A30** | Ampere | 24GB HBM2 | 主流推論 |

**DGX 系統：**
- **DGX H100**：8x H100 GPU，NVLink + NVSwitch 互連
- **DGX SuperPOD**：多台 DGX 透過 InfiniBand 組成超級叢集
- **DGX BasePOD**：參考架構，企業級 AI 基礎設施起點

### 2.2 擴展 GPU 基礎設施

**Scale Up vs Scale Out：**
- **Scale Up（向上擴展）**：增加單一伺服器的 GPU 數量（NVLink、NVSwitch）
- **Scale Out（向外擴展）**：增加更多節點/伺服器（InfiniBand、RoCE）

**GPU 互連技術：**

| 技術 | 範圍 | 頻寬 | 用途 |
|------|------|------|------|
| **NVLink** | GPU 對 GPU（同節點） | 900 GB/s（H100） | 高速 GPU 直連 |
| **NVSwitch** | 節點內所有 GPU 互連 | 全交換 | DGX 系統內部 |
| **PCIe** | GPU 與 CPU 之間 | Gen5: 128 GB/s | 通用互連 |
| **InfiniBand** | 跨節點 | 400 Gb/s（NDR） | 高效能叢集網路 |

### 2.3 電力與冷卻

**電力考量：**
- 單顆 H100 GPU 功耗：約 700W（SXM 版本）
- DGX H100 系統功耗：約 10.2 kW
- 資料中心需要足夠的電力供應和備援（UPS、發電機）
- PUE（Power Usage Effectiveness）= 總電力 / IT 設備電力（理想值接近 1.0）

**冷卻方式：**
| 方式 | 說明 | 適用 |
|------|------|------|
| **氣冷（Air Cooling）** | 傳統 CRAC/CRAH 空調 | 中低密度機架 |
| **液冷（Liquid Cooling）** | 直接接觸冷卻 | 高密度 GPU 伺服器（DGX H100） |
| **浸沒式冷卻** | 整機浸入冷卻液 | 極高密度部署 |
| **後門散熱器（RDHx）** | 機架後門的液冷設備 | 改造現有設施 |

### 2.4 On-Prem vs Cloud

| 面向 | On-Prem（地端） | Cloud（雲端） |
|------|----------------|---------------|
| 資本支出 | 高（CAPEX） | 低（OPEX 按用量付費） |
| 控制權 | 完全控制 | 有限控制 |
| 安全性 | 資料不出廠 | 依賴雲端供應商 |
| 擴展性 | 受限於硬體 | 彈性擴展 |
| 維護 | 自行維護 | 供應商維護 |
| 適合 | 穩定工作負載、資料合規 | 變動工作負載、快速部署 |
| 混合雲 | 結合兩者優勢 | — |

### 2.5 網路需求與協定

**AI 工作負載網路需求：**
- **低延遲**：GPU 間通訊需極低延遲
- **高頻寬**：大量梯度和模型參數傳輸
- **RDMA（Remote Direct Memory Access）**：繞過 CPU，直接記憶體存取

**網路技術：**

| 技術 | 說明 |
|------|------|
| **InfiniBand** | 最高效能的叢集互連，支援 RDMA，NVIDIA 主導 |
| **RoCE（RDMA over Converged Ethernet）** | 在乙太網上實現 RDMA |
| **Ethernet（乙太網）** | 通用網路，成本較低 |
| **NVIDIA Spectrum-X** | 針對 AI 最佳化的乙太網平台 |
| **NVIDIA Quantum** | InfiniBand 交換器平台 |

**InfiniBand 速度演進：**
- EDR: 100 Gb/s
- HDR: 200 Gb/s
- NDR: 400 Gb/s
- XDR: 800 Gb/s

### 2.6 DPU（Data Processing Unit）

- **全名**：NVIDIA BlueField DPU
- **定位**：資料中心的「第三顆處理器」（CPU、GPU、DPU）
- **功能**：
  - 網路加速和卸載
  - 安全和加密
  - 儲存加速
  - 虛擬化支援
- **優勢**：將基礎設施任務從 CPU 卸載，釋放 CPU 給應用程式

### 2.7 叢集關鍵組件

1. **GPU 伺服器**：DGX 或 HGX 系統
2. **高速網路**：InfiniBand / RoCE 交換器
3. **儲存系統**：高效能平行檔案系統（GPUDirect Storage）
4. **管理節點**：叢集管理和工作排程
5. **冷卻系統**：液冷或氣冷
6. **電力基礎設施**：PDU、UPS、發電機

### 3.4 GPU 虛擬化

**NVIDIA vGPU 技術：**
- 將實體 GPU 分成多個虛擬 GPU 實例
- 支援多租戶共享 GPU 資源
- 適用於 VDI（虛擬桌面基礎設施）和 AI 工作負載

**MIG（Multi-Instance GPU）：**
- 可用於 A100/H100
- 將單顆 GPU 分割成最多 7 個獨立實例
- 每個實例有獨立的記憶體、快取和運算資源
- 提供硬體層級的隔離

**MIG vs vGPU：**
| 特性 | MIG | vGPU |
|------|-----|------|
| 隔離層級 | 硬體 | 軟體（虛擬化） |
| 支援 GPU | A100/H100 | 多種 GPU |
| 需要 Hypervisor | 否 | 是 |
| 最大實例 | 7 | 依 GPU 型號 |
